# 本轮经验

2026-11-06，书房 TV 云盘与阅读体验集成。

1. **合并关系和交互验证分别检查。** 分支名相似不代表内容重复；先看祖先和工作区状态，保存独立提交后合入最新 main。无文本冲突仍可能留下共享页面的产品遗漏。
2. **排版只用一份规则。** ReadingStyle 同时供阅读器和全局设置使用。本书覆盖与全局默认分别持久化，避免设置页改了默认却悄悄覆盖一本书。
3. **选中状态与焦点分开。** 当前值用琥珀标记，遥控器焦点用浅色边框；重建页面用稳定的书籍/收藏/设置 ID 恢复，不能依赖控件序号。立即滚动可避免小屏当前项暂时只露出一半。
4. **原文位置比页码稳定。** EPUB 章节、UTF-16 文字位置、TXT 段首字节是持久锚点；调字号、栏宽和纸色不重写这些位置。Unicode 代理对、异步迟到回调、跨段保存均需覆盖。
5. **系统控件必须按真实 Android 行为验证。** AlertDialog 的 message 与 list 默认互斥；长摘录需要受限预览和独立备注区域。网页原型不会暴露这类原生问题。
6. **暂停原因分别保存。** 自动翻页的菜单暂停可以自动恢复；手动暂停、手动翻页、应用后台和朗读互斥有不同恢复条件。只用一个布尔值容易意外继续。
7. **功能入口要全局复查。** 阅读器已有栏宽和新功能，不代表设置、关于、指南都同步了。发布前同时检查版本号、默认值范围、首次启动与空状态。
8. **设计、JVM 与设备证据各有边界。** OpenDesign 确认结构和视觉；Robolectric 检查原生布局和边界；实际电视才验证系统服务、Binder、文件选择器和真实遥控事件。缺少中文 TTS 引擎必须写成环境限制。
9. **发布身份和签名按所有权核对。** spudhero 仓库使用对应作者、提交者和 GitHub 账号；开发机默认 debug 密钥可能与已发布 APK 不同，覆盖安装前核对证书，保留历史文件。
10. **能解析 Intent 不代表具备系统能力。** Sony 的 OPEN/CREATE_DOCUMENT 指向电视占位组件，会直接返回。只识别已知占位包；查找结果为空时仍尝试原流程，避免包可见性导致误判。导出缺少界面时不创建快照，保留收藏并解释恢复办法。
11. **主题封装也要保留状态和回调。** 原生 `setTitle()` 不会更新自定义标题，进度须走统一更新入口；表单若覆盖对话框的 OnShow 监听，会丢掉通用样式。先显示再绑定按钮校验，并给自定义内容和列表相同高度上限。
12. **断网验收要真正停止服务。** 在线 TXT 的 48 KiB Range、下载前只有指南、下载后字节/哈希匹配、关闭服务后原文位置和冷启动恢复共同证明存储规则。只看到“离线”标签或小 EPUB 一次读取完都不足以下结论。
13. **自动行为用位置序列验证。** 5 秒间隔下记录运行、开菜单、关菜单、手动暂停的 offset，比肉眼看截图更可靠；本次分别得到推进、保持、恢复、保持，符合用户选择的暂停策略。
14. **连接可用与共享可用是两个状态。** SMBJ 连接仍报告 connected 时，共享可能已因空闲超时关闭；无 cause 的运行时异常因此不能只看 cause 分类。精确结合异常类型和共享状态，仍只重连一次，保留身份错误与文件变更检查。
15. **打开成功、正文可见、实际可读分别验收。** 漫画的 ZIP/目录能加载不代表图片能显示；竖版 PDF 整页渲染正确也不代表电视上小字易读。真实长元数据还能暴露短测试标题没有覆盖的裁切。
16. **警告不能改写原文。** 章节是否含图片的标记与正文分开，让界面解释限制并保留文字锚点。漫画章节末尾也可能有少量文字，不能只判断“纯图片”；测试连续翻过纯图片、图文混排与纯文字，确认提示持续、撤销且焦点恢复。

实机结果、截图和保留边界见 [集成记录](INTEGRATION-2026-11-06.md)。临时服务、来源、测试书籍和端口转发已清理；参考应用与用户数据没有进入公开仓库。

后续真实 SMB 来源和阅读记录按用户要求保留；实际书页截图及逐本报告留在本地，不发布到公开仓库。汇总见 [SMB 补充验证](SMB-DEVICE-VALIDATION-2026-11-06.md)。

## 图片、PDF 与 Kindle 格式增量

17. **能力说明不能替代必要的阅读能力。** 第 16 条是图片尚未实现时的历史处置；当前必须显示真实位图。解析模型把图片资源与稳定文字锚点分开，渲染器按顺序排入图文屏，失败提供重试，不能把占位符当成图片通过。
18. **先弄清原生缓冲区的所有权。** libmobi 重建资源会借用原始记录。提前释放 MOBIData 后，元数据看似成功，后续打开图片却访问失效内存；会话必须同时持有原始和重建数据，按相反顺序释放。
19. **格式识别不是目录支持。** 旧 MOBI 常把全文放在一个 HTML 中，仍可有完整 NCX。用目录锚点拆章并保留前言和全部原文，才能让目录跳转真正进入相应正文；不能只显示“第 1 章”冒充支持。
20. **PDF 放大只渲染可见区域。** 100% 定义为屏宽，而不是 PDF 点数或整页；平移矩阵交给 PDFium，内存与屏幕面积关联，避免 300% 整页位图。设备像素测试验证上下区域和放大后取景，几何单测不能替代实际渲染。
21. **封面和漫画需要不同的初始视图。** 有些封面源图带大块上沿空白，统一屏宽会让首屏近似空白。普通图片先完整适配，密集画页先屏宽，并允许本书手动切换；必须查看实际截图才能发现问题。
22. **测试工具也要保护设备状态。** 应用与 instrumentation 使用同一已有开发密钥；生成的 PDF 测试文件在 finally 中清理。原生库和系统 PDFium 在 Sony 上验证，Robolectric 覆盖图片布局、锚点、迟到回调及旧数据迁移。
23. **实书验收要保留逐本位置证据。** 加载、翻页/滚动和退出重开分别截图并比较章节、文字偏移、图片偏移及 PDF 缩放坐标；只看成功标题不够。公开记录只放汇总和合成内容，真实书页、文件名和来源凭据留在本地忽略目录。
24. **升级 APK 不会更新已生成的指南文件。** 指南被保存成普通本地 TXT，只改创建入口会让旧用户继续读到旧能力说明。打开自带指南时重新生成，并同时核对作者、格式、来源、URI 和应用内文件名；同名用户书籍不得被覆盖。回归通过真实阅读入口和遥控返回事件验证，不能用桌面文件 API 或绕过应用输入流程代替。

## UI 与语音准备状态复核

25. **一个页面修过长标题，不代表其他页面已经覆盖。** 阅读页单行省略并未修复首页固定高度的两行标题。首页采用自然高度和两行省略，分别检查 1080p/720p，断言标题、作者、进度和按钮不重叠，同时保留原始元数据。
26. **发现服务、支持中文和实际发声分别验收。** 系统声明 TTS 服务只用于设置提示；开启时仍检查中文语言数据，再获取音频焦点。模拟器的成功回调不证明电视能发声。设备没有引擎时，应在点击前说明条件，而不是先显示正在准备播放。
27. **按格式显示真正有效的控制。** PDF 原始页不会跟随文字纸色变化，因此只显示阅读亮度；不能让同一个菜单对不同格式承诺相同效果。帮助、菜单和实际方向键行为要一起核对。
28. **设计参考和公开证据使用合成内容。** 原生实机截图可能携带私人书名和阅读历史。交给设计工具前改用已检查的原创指南/合成书籍；私人截图保留本地。启动器横幅也需要单独验收名称可读性，不能用应用内部标题代替。

29. **原始设计建议与原生验收分开记录。** 原型的返回退出平移、整块亮度模拟、纯图片能力不能直接覆盖现有阅读器的混排与缩放语义。保留设计原稿，另列落地映射，并用真实 View / Sony 截图校正帮助。
30. **启动器检查要落在实际应用列表。** 资源能编译不等于电视入口清楚；除了图标遮罩，还需查看已安装横幅的应用名、尺寸和点击启动。多密度资源移目录后遇到陈旧合并缓存时，定向重跑资源任务即可验证，不应删除整个开发缓存。

## 书架封面

31. **解析过封面，不等于界面显示过封面。** 书内插图和书架 CoverView 原来是断开的，后者始终绘制通用文字图。验收必须经过真实提取、缩略图缓存、首页与书库绑定，不能只断言 coverPath 非空。
32. **缩略图与阅读内容使用不同预算。** 书架只读可见封面，限制尺寸和内存 / 磁盘缓存；Kindle 按资源记录偏移取封面，PDF 用完整第一页，不能为缩略图重建全文或套用当前阅读视口。缓存说明须同步到存储文档。
33. **后台队列隔离也要检查共享锁。** 原图片解码器整段 synchronized，在新增封面队列后会让一个网络读取阻塞另一本文字书的插图。仅锁住 AndroidSVG 的全局解析器，并用阻塞封面 / 并行正文图片的测试验证。
34. **失败不能永久冒充没有封面。** 网络异常不写空缓存；冷启动应能复用已有缩略图，稍后重新进入页面允许重试。真实书籍逐本检查，公开证据使用原创封面，同时核对封面加载前后书库和书签完全相同。

## 独立语音与模型实测

35. **模型能加载不等于适合电视。** 候选 MeloTTS 在 Sony ARMv7 上 RTF 约 22.7，实测后改用 AISHELL-3 low VITS，最终样本 RTF 约 0.50。模型选择要同时说明速度、8 kHz 音质与中文范围，不能只比较压缩体积。
36. **下载成功仍需识别模型内容。** 某上游归档包含 Git LFS 指针而非权重，单看下载状态和文件名会误判。固定真实字节数及哈希，安装与 JNI 加载前分别校验；不把指针作为可用模型。
37. **合成完成与播放完成是不同事件。** PCM 写入 AudioTrack 后尚有缓冲。用实际播放指针更新短句位置和段落完成，测试中冻结播放指针，确认不会提前高亮或读下一段。
38. **取消也涉及原生所有权。** 不能在 ONNX 推理中销毁句柄；取消后丢弃结果，合成串行队列最后释放。播放端立即暂停/清空，网络端取消 Call；队列限制预取量，避免长章节生成全部音频。
39. **归档压缩体积不能代表安装成本。** 31 MiB 下载内有未用的 172 MiB 规则文件；受限遍历但不落盘。旧电视首次解压仍需数分钟，因此显示真实校验阶段，不编造速度、剩余时间或就绪状态。
40. **焦点与选用状态必须分别呈现。** OpenDesign Cloud 提供侧栏、滚动内容与固定主操作；浏览和保存 Azure 配置不自动选用，离线失败也不切换网络。720p 保留首屏操作，完整许可可离线查看。

## 4K 内容与显示链路

41. **面板、UI、内容缓冲区和最终输出要分别验证。** Sony 面板为 4K，普通应用仍得到 1080p。SurfaceView 与 PixelCopy 能证明 UHD 源像素，却不能证明 HWC 最终逐像素输出；必须核对合成类型、目标帧与 source crop，不能用“缓冲区创建成功”宣称原生 4K。
42. **保留逻辑坐标，提高最终绘制精度。** 正文字形直接画到高清 Canvas，PDF 按高清视口重新渲染，SVG 按目标尺寸栅格化；字号、分页、朗读与书签坐标保持一致。把低分辨率位图放大或把所有 dp 翻倍都不能替代这条路径。
43. **高清渲染不应隐藏输入控件。** alpha=0 会影响 Android 无障碍可见性。保留原 View 的焦点与描述，只关闭其重复绘制；使用 Surface 生命周期和实际首帧结果切换显示，失败时恢复普通路径。
44. **高密度截图需要检查真实字体行高。** 首页最近阅读标题、底部进度栏的固定像素高度，在 4K 密度下会裁字；改成 dp，并用实际字体行高断言。封面也要按密度区分缓存，避免沿用较小缩略图。
45. **状态刷新必须在内容变化时发生。** 显示面板定时读取实际状态可以保留，但文字没变时不反复 setText，否则造成额外布局和无障碍事件，影响设备稳定等待与自动化验收。
