# 4K 展示与阅读绘制验证

开发版本：`0.5.0-alpha.2` / 版本码 9。这次增加独立高清阅读绘制、显示设置、原生 4K 布局验证，并修正高密度界面的两处文字裁切。

## 实现与边界

面板、系统界面、应用内容缓冲区和最终输出是不同环节。Android 官方说明，一些 4K 电视给应用分配较低分辨率的 UI，SurfaceView 可以单独使用更高分辨率的缓冲区；这不保证每台电视最终按原生 4K 合成。[Display.Mode](https://developer.android.com/reference/android/view/Display.Mode#getPhysicalWidth())、[SurfaceHolder.setFixedSize](https://developer.android.com/reference/android/view/SurfaceHolder#setFixedSize(int,%20int))。

- `ReadingResolution` 保留现有逻辑坐标，按面板与系统画布的比例选择内容像素，独立画布限制在 UHD 视口以内。已有原生 4K UI 不再创建额外放大层。
- `ReadingSurface` 在主线程调用独立 Surface 的硬件 Canvas。正文重新绘制字形，未把 1080p 截图放大；实际尺寸匹配且首帧提交后才显示“4K 内容绘制”。文字阅读只覆盖正文区域，实际尺寸会小于全屏 UHD。
- PDF 按实际阅读画布生成视口位图，最多 3840×2160；默认 100% 适合屏宽，上下滚动，放大后左右平移。位置使用归一化坐标，切换清晰度不改变阅读位置。
- SVG 可按目标尺寸重新栅格化；光栅插图最多 8,294,400 像素，不会为低分辨率原图虚构细节。高密度界面的封面使用 512×768 上限及独立缓存键，普通密度仍使用 384×576；共用原有 8 MiB 内存、64 MiB 磁盘预算。
- 普通阅读控件继续负责遥控器输入和无障碍描述，只跳过重复绘制，不通过零透明度把正文控件隐藏。保留搜索、朗读高亮、自动翻页和书签的原文坐标。
- 创建或绘制失败、确认超时会恢复系统画布；高清 PDF / 插图分配不足时尝试较低分辨率，仍失败则提供可重试的错误。兼容模式可主动恢复原显示方式；失败后可以重新尝试。
- 首页“最近阅读”和阅读页进度栏原先使用固定像素高度，现改为 dp；原生 4K 测试检查实际字体行高，避免裁字。

不修改电视的全局 `wm size`、密度或固件。未更换开发签名，不清空应用或书库。

## OpenDesign 原型与原生落地

本次通过 OpenDesign Cloud / Local Codex 完成 [交互原型](../design/display-4k.html)与[原始规格](../design/DISPLAY-4K.md)，保留暗色书房、琥珀选中、暖白焦点。新增设置和阅读菜单里的“显示与清晰度”：自动 / 兼容、当前效果、折叠设备详情、固定返回按钮。未打开书籍时明确等待实际阅读确认。

原始稿中的“高清阅读 4K”在原生产品改为“4K 内容绘制”，并说明最终显示精度由电视系统决定。原型的设备状态、超时和 PDF 是合成演示；不把网页模拟当作实机证据。浏览器预览已核对；原生实现差异见 [落地映射](../design/NATIVE-ADOPTION.md)。

## Sony 实机结果

Sony BRAVIA 4K UR2、Android 10 / API 29、ARMv7：面板能力 3840×2160，系统 UI 实际为 1920×1080、320 dpi，公开显示模式也只列出 1080p。

| 环节 | 观测结果 |
| --- | --- |
| 全屏独立 Surface | 成功提交 3840×2160；PixelCopy 验证一整行 3840 个交替黑白像素全部正确，不是放大的 1080p 栅格 |
| 文字正文 | 独立阅读区 3456×1468；兼容模式 1728×734，字号与原文位置不变 |
| PDF | 全屏阅读缓冲区及视口位图 3840×2160；屏宽滚动与缩放沿用原有交互 |
| 最终合成限制 | SurfaceFlinger 接收到高清源，但 HWC 记录为 CLIENT 合成，目标仍为 1920×1080；这台固件会再次缩放，不能声称已实现最终原生 4K 输出 |

因此已证明应用具备 4K 内容绘制和原生 4K 布局能力，尚未证明这台 Sony 最终逐像素显示 4K。普通 `screencap` 仍为 1920×1080，不能靠截图尺寸判断独立源缓冲区，也不能把 PixelCopy 当作面板输出证明。最终观看距离、主观清晰度和其他电视的硬件合成路径仍需要对应设备验证。

224 项 JVM / 原生界面测试（core 53、app 171），lint 0 错误、19 警告，四 ABI APK 和 AndroidTest 构建通过。`DisplayDeviceTest` 验证独立缓冲区的一像素细节；`ReaderDeviceTest` 验证 PDFium 与原生 Kindle；`SpeechDeviceTest` 保留真实语音回归。

最终 APK SHA-256：`36d57d81bbae8449554f363426ed807e88e6cffd67c7c83d2f7cb822c0b94099`。开发证书 SHA-256：`9aeb612cabfb2d39bd0d7b40f212a562c0aee3440a9bd4b84e376f335ab6e0e0`。

最终设备测试 **5 / 5 通过**，覆盖高清缓冲区、PDFium / Kindle 和独立语音真实播放回归。安装版本为 `0.5.0-alpha.2` / 9，设备 APK 与上述 SHA-256 一致。

真实 SMB 回归覆盖 AZW3、MOBI、图文 EPUB、纯图片漫画 EPUB 和 PDF：加载、翻页与图片移动正常；PDF 屏宽滚动、200% 缩放和平移、恢复 100% 通过。原创指南与 PDF 的自动 / 兼容切换保留原文位置、页码、缩放及平移；遥控器可滚动查看全部设备详情。PDF 阅读后的单次进程内存快照为约 147.5 MiB PSS，仅作当前状态记录，不代表峰值或长期稳定性测试。
