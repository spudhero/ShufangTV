## 使用

1. 设置 → 朗读与语音 → 管理朗读语音，默认“离线中文”。
2. 首次下载约 30.1 MiB，安装约 31.2 MiB，建议预留 120 MiB。校验 / 解压在旧电视上可能需要数分钟；离开面板继续下载。取消后重新下载，不支持断点续传。
3. 就绪后先“试听中文”；在文本书籍的阅读菜单选择“朗读正文”。语速和定时在“朗读设置”。
4. 进入后台、手动暂停后需主动继续；更换引擎不会自动恢复朗读。下载或离线失败不回退网络。
5. 网络语音需自己的 Azure Speech 资源地区和密钥。保存配置与浏览页签不改变当前选择，必须点击“选为当前”并确认段落外发及可能计费。仅保存配置不证明服务可用。

## Sony 设备与性能

BRAVIA 4K UR2 · Android 10 / API 29 · 1920×1080 / 320 dpi · `armeabi-v7a`。系统查询 TTS 服务结果为 `No services found`。

最终包设备测试结果：`ReaderDeviceTest` 2 项、`SpeechDeviceTest` 2 项，17.791 秒，`OK (4 tests)`。包括真实 PDFium 视口 / 完整缩略图、原生 Kindle 解码、中文与日期数字合成、1.5 倍语速缩短音频，以及实际 AudioTrack 播放指针前进后取消不会完成旧请求。

| 指标 | 最终 Sony 样本 |
| --- | --- |
| 原创文字 | 夜幕降临，书房亮起一盏灯。 |
| 采样率 | 8,000 Hz，16-bit 单声道 |
| 初始化 | 5,792 ms |
| 合成时间 / 音频时长 | 1,186 ms / 2.429 秒 |
| RTF | 0.488；小于 1 表示合成比播放快，仅代表本样本 |

[实际 Sony 合成样音](audio/sony-offline-chinese.wav) · [原始指标](audio/sony-offline-metrics.json)。模型包含随机韵律，重复运行时长会略有不同；测试确认输出非静音和快语速更短。没有把桌面机器的速度冒充电视性能。

首次候选 MeloTTS Chinese INT8 在同一 Sony 上约 52 秒合成 2.3 秒音频（RTF 22.7），因此未作为发布默认包。当前轻量模型优先保证这台 ARMv7 电视的可用速度，8 kHz 音质与中文范围是明确取舍。没有将已下载的权重或预编译库加入 Git。

语音包实际走应用下载入口，完整归档 / 各文件校验并安装，第 175 秒截图已观察到就绪。归档内未使用的 172 MiB `rule.far` 不落盘。启动先检查完成标记和文件长度，加载 JNI 前重新计算所有安装文件哈希。

## 实现与验证边界

- `SpeechEngine` 统一离线 / Azure / 系统后端；继续使用现有 Narration 的 UTF-16 原文范围、令牌、媒体会话、焦点和定时规则。
- 首个片段限制 16 个 Unicode 码点，其后 36 个；串行合成与播放分别运行，队列最多预取两个片段。实际播放指针前进后才高亮，音频排空后才推进段落。
- 原生单句推理不能中途终止；取消后丢弃结果，排队释放句柄。停止立即清空 AudioTrack；旧请求不能迟到重播。
- 包安装使用固定上游 URL、归档 SHA-256、逐文件长度 / SHA-256、受限解压和原子替换。载入前校验，活跃朗读租约阻止删除 / 重装。完整 Apache / MIT 许可随 APK 提供，可在管理页离线查看。
- Azure 使用官方 HTTPS 端点，不跟随带密钥的重定向；SSML 转义、认证 / 限流提示、取消、音频长度与类型边界均有测试。配置 AES-GCM 加密，音频仅在内存。没有真实 Azure 资源凭据，不能宣称线上语音已通过。
- PDF 与纯图片不新增 OCR；原有插图、漫画与 PDF 阅读保留。离线包只承诺中文；背景播放、断点续传、多离线音色和高保真模型未在本轮实现。
- ARMv7 已执行，ARM64 / x86 / x86_64 只确认构建。实际扬声器听感以样音及用户现场试听为准；自动化指标不替代人耳评价。

构建运行 `:core:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest`（JDK 17、SDK 36、原开发密钥）。215 项测试为 core 50 + app 165。22 个 lint 警告中新增 1 个为保守空闲空间检查的 `UsableSpace` 建议，其余为既有布局、绘制与本地化建议。
