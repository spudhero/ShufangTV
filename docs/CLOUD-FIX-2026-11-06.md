# 网盘故障修复与 Sony 验证

2026-11-06，`0.5.0-alpha.3` / 版本码 10。设备为 Sony BRAVIA 4K UR2、Android 10 / API 29；沿用原开发签名覆盖安装，保留 SMB 来源、书库、阅读进度、书签和语音模型。

后续 `alpha.4` 修复选择页仅显示子文件夹、隐藏同目录书籍的交互问题，当前结果见[书籍显示修复](CLOUD-BOOKS-2026-11-06.md)。本页保留 alpha.3 的登录与目录阶段证据。

## 已确认的问题

| 网盘 | 实际失败点 | 修复 |
| --- | --- | --- |
| 阿里云盘 | 已保存账号；设备会话 HTTP 200、`success=true`、`result=true`、`code:null`，却报“阿里云盘暂时无法完成请求（null）” | 先识别 JSON 空错误码，再校验设备结果；保留权限错误与单次会话重建规则 |
| 百度网盘 | 未扫码时约 30 秒才返回 `errno=1`，原 30 秒读取超时会提前失败；手机确认及交换成功；旧模板接口返回 `errno=-6`，而相同会话的当前身份与目录接口均成功；目录筛选参数还会切换到精简条目结构 | 仅扫码长轮询改为 40 秒读取超时，整体仍限 45 秒；取得 BDUSS 后直接验证个人盘 API；旧模板 -6 时核对当前 loginStatus，重试保留已交换阶段；目录使用完整条目并本地筛选 |
| 夸克 | 扫码确认和票据交换均成功，但真实账号响应没有 `data.uid`，旧实现报“账号编号不正确” | 兼容首方站点匹配的有效 `__uid` Cookie；仍验证 API 会话和个人盘 config，不用凭据 `__kps` 充当账号编号 |
| UC | 本轮已保存账号目录请求成功 | 保持连接器行为并回归检查 |

同一条“网络暂时中断”曾覆盖以上不同异常。扫码页重试文字改为“扫码状态获取失败，正在重试…”，不再据此断言网络中断；最终失败仍显示经过限制的具体原因。没有改动页面布局。

夸克身份字段依据另见[首方桌面脚本](https://g.alicdn.com/uc-cloud-drive-web-system/cloud-drive-web/4.6.7/share.js)；协议与本轮真实响应分别核对，不用脚本字段推测代替设备验证。

## 实机结果

- 阿里：使用已保存真实账号，设备会话恢复，读取 2 个分区并进入资源库看到 3 个文件夹；电视“选择书籍文件夹”页面显示正常。
- 夸克：用户手机扫码确认；保留同一次已确认会话，在修复后重新执行官方账号和 config 验证，通过后加密保存账号；根目录读取 6 个条目，电视目录选择正常。临时恢复代码和会话明文已从交付代码及设备缓存清理。
- 百度：连续约 30 秒长轮询保持等待，真实手机扫码与确认；使用同次已确认会话完成当前身份验证和加密保存。最终只读探针读取第一页 100 个文件夹，仍有后续页，不能当作全盘总量；电视显示真实名称，下一页和进入子目录通过。
- UC：已保存真实账号根目录读取成功。

这些结果证明列出的登录和目录阶段。原文件读取链接、Range、会员/风控限制、会话长期过期和全部格式的在线阅读不在本轮已完成范围内。早期匿名检查和本地协议夹具不能作为这些场景已通过的证据。

`CloudDiag` 只记录固定的网盘与接口阶段、HTTP/业务状态码、已知扫码状态、异常类型；相同记录限流，最多保留 64 个去重项。它不记录 URL、账号、目录名、令牌、票据、Cookie 值、原始响应或异常堆栈。

只读设备探针默认不执行账号请求；显式运行：

```sh
adb -s DEVICE shell am instrument -w -r \
  -e cloudProbe true \
  -e class io.github.spudhero.shufangtv.cloud.CloudDiagnosticDeviceTest \
  io.github.spudhero.shufangtv.test/androidx.test.runner.AndroidJUnitRunner
```

可加 `-e cloudProvider aliyun` 等限定单个网盘。探针只读目录或匿名生成/轮询二维码，并按正常读取流程加密保存令牌/Cookie 轮转，不下载、修改或删除云盘文件。私有结果位于应用 `cache/cloud-diagnostic-probe.json`；必须检查各网盘 `success`、阶段和计数，不能把测试运行器的 `OK` 等同于账号已授权。完整日志、账号与目录截图放在本地忽略目录，不进入公开仓库。
