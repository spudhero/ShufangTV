# 书房 TV · 显示与清晰度

本次是既有暗色书房的局部增量，交付入口为 [display-4k.html](display-4k.html)。浏览器是可交互设计载体；本页没有 Android Surface、真实 PDF 渲染器或电视检测能力，全部书名、正文和设备状态均为合成示例。

## 文件与使用

| 文件 | 用途 |
| --- | --- |
| `display-4k.html` | 设置概要、独立显示面板、阅读菜单及 PDF 操作示例 |
| `assets/display-4k/display-4k.css` | 局部布局、dp/sp 尺度、三种目标画布与焦点样式 |
| `assets/display-4k/display-state.js` | 用户偏好与实际阅读画布分离的状态模型 |
| `assets/display-4k/display-4k.js` | 页面、遥控器导航、确认流程与审核模拟 |
| `DISPLAY-4K.md` | 本规格 |

直接打开 HTML 即可；不依赖网络或安装依赖。初始为 Sony 合成设备、自动模式、尚未进入阅读，默认焦点在“打开阅读示例”。首次进入阅读用约 1.8 秒演示确认流程。页面刷新后恢复初始样例，不把前一次确认持久化为设备事实。

画布外工具可以切换设置概要 / 显示面板 / 阅读菜单、目标尺寸、成功 / 兼容 / 回退 / 原生 4K 系统等状态，以及后续成功、失败或超时的模拟结果。“正在确认（固定样例）”保持等待状态，用于审核文案；选择其他样例或重新进入阅读流程可继续演示。所有这些工具均不进入原生产品。

尺寸工具只改变设计预览的逻辑画布，不改变合成电视状态；选择 4K 目标画布并不会自动让设备状态显示 4K。画布按浏览器可用宽度缩放，桌面预览的 CSS 像素不能当作电视实际像素采集值。

首页、书库和语音入口以新窗口链接既有原型，保留本页阅读位置。本次只新增以上文件；既有 `index.html`、`ui-review.html`、`speech-offline.html`、共享 tokens、书架、云盘和语音操作均未改动。

## 已确认事实与本次选择

- 用户提供的目标 Sony Android 10：面板 3840×2160，普通系统 UI 1920×1080。这是本次设计输入，未通过本页查询电视。
- 常规设计画布 960×540dp；1280×720@2 对应独立的 640×360dp 紧凑布局。
- 保留现有暗色书房、暖白正文、琥珀已选、浅色焦点；按钮至少 44dp，标签至少 12sp。
- 默认“自动（推荐）”；“兼容模式”用于显示异常时退回原有阅读。它不是画质等级切换，也不修改全局系统分辨率。
- 新增布局、2dp 焦点线、确认超时建议与分块尺寸是本次实现选择，非既有品牌规范或已完成的电视测试结论。

Android 官方说明：一些 Android TV 的 UI 层低于显示屏分辨率并被放大；SurfaceView 可承载独立的高分辨率内容。该文档讨论视频 Surface，支持本设计区分 UI 与内容画布的依据；它不保证自绘阅读在特定 Sony 上成功，阅读实现仍需原生验证。[Android Surface types](https://developer.android.com/media/media3/ui/surface)

## 高优先级改动

| 优先级 | 改动 | 读者可见结果 |
| --- | --- | --- |
| P0 | 分离已选模式、请求目标、实际阅读结果 | 选中自动后不会立即出现 4K 成功文案 |
| P0 | 实际尺寸与首帧完成共同确认 | 只有独立阅读画布确认为 3840×2160 且成功绘制后，才称“高清阅读 4K” |
| P0 | 清除过期回调与失效画布结论 | 切模式、退出阅读、重建或后台恢复后，旧 4K 标记不会复活 |
| P0 | 明确并验证回退结果 | 高清失败先显示恢复中；原有阅读恢复完成后才显示已回退 |
| P0 | 保持相同逻辑字号 | 高清画布增加细节，字号、行距、栏宽与阅读位置不缩小 |
| P1 | 独立滚动显示面板 | 设置概要只保留入口和所选模式；完整说明集中在一个面板 |
| P1 | 阅读菜单只增加清晰度摘要入口 | 原书架密度、语音控制与其他阅读功能维持既有职责 |
| P1 | PDF 屏宽与分块放大 | 100% 适合屏宽，长页上下滚动，放大后平移 |

## 界面与信息层级

### 设置概要

保留主侧栏。“显示与清晰度”显示当前选择的“自动（推荐）”或“兼容模式”，辅助说明“打开书籍后确认实际阅读效果”。按确定进入独立面板。此处不把面板的 4K 能力当作当前阅读效果。

“朗读与语音”沿用既有管理入口。暂停、上下段、语速、定时仍属于阅读会话，不放进显示面板或全局显示设置。

### 独立面板

顺序为：标题与作用范围 → 当前效果 → 两个模式 → 折叠设备详情 → 短帮助。底部保留主动作和返回，不与中间内容争用滚动空间。

- 自动（推荐）：按电视能力尝试高清阅读；未能启用时使用原有阅读方式。
- 兼容模式：显示异常时，退回原有阅读方式。
- 确定即改变选择，不增加额外“应用”步骤。未打开书籍时只保存偏好；阅读会话内更改时进入新的确认流程。
- 设备详情只有“电视面板 / 系统界面 / 实际阅读画布”三行；没有请求尺寸、线程、缓存、Surface、bitmap 等面向实现的字段。
- 未进入阅读时，实际阅读画布为“未进入阅读”，当前效果为“进入书籍后确认”；从阅读菜单进入且原会话仍有效，可展示当前实际结果。
- “返回阅读”直接回正文；“返回阅读菜单”和返回键恢复清晰度入口的焦点。初始从设置进入时，返回键回到原设置入口。

在原生中，阅读内面板属于当前阅读会话。若底层画布仍有效，保留实际结果；若打开面板导致画布被销毁，必须立即清除确认状态，返回阅读后重新确认。原型用“模拟画布重建”演示失效与重新确认。

### 阅读菜单

在既有“显示”分组中插入“显示与清晰度”，主标签固定，第二行由实际状态派生，不增加大面积徽标或“4K 开关”。

| 真实状态 | 菜单第二行 |
| --- | --- |
| 独立画布 3840×2160 且有效、首帧绘制完成 | 高清阅读 4K |
| 系统阅读确认完成，包括原生 4K 系统 | 系统清晰度 |
| 请求中、重建中、恢复中、尚未完成确认 | 清晰度确认中 |
| 原有阅读也未恢复 | 显示暂不可用 |

原生 4K 系统不伪装成新启用的独立高清路径：菜单仍写“系统清晰度”，设备详情的系统与实际阅读画布可同时显示 3840×2160。

打开菜单时正文不重新排版、不改变分页。工具以系统 UI 层覆盖正文右侧，不用剩余窄区域重新计算 PDF 的 100%。关闭菜单后位置保持。原生朗读、书签与其他工具继续使用原有事件和数据；本页只演示清晰度、位置书签与跳转的合成状态，语音完整交互链接原交付。

## dp / sp 与像素换算

以下以系统字体缩放 1.0 为基准。正式实现使用 sp 处理文字，并考虑系统字体缩放，不用像素硬锁控件高度。

| 目标输出 | 逻辑布局 | 设计密度 / 阅读绘制比例 | 正文 22sp | 操作高 44dp |
| --- | --- | --- | --- | --- |
| 1920×1080 @2 | 960×540dp | 2 px / dp | 44px | 88px |
| 3840×2160 @4 | 960×540dp | 4 px / dp | 88px | 176px |
| 1280×720 @2 | 640×360dp | 2 px / dp | 44px | 88px |

前两行中，正文占横向画面的比例同为 `22 / 960`，按钮占高度的比例同为 `44 / 540`。因此在相同屏幕、同样全屏显示条件下，设计观看尺寸保持一致，像素细节增加。720p 是紧凑布局，减少侧栏宽与留白，不把 960×540 整体缩成更小的字与按钮。

**Sony 独立画布不等于 Android 全局 density 改成 4。** 普通 View 继续使用设备当前 density=2。高清阅读的有效绘制比例为 3840/960=4；若现有正文已经按普通 UI 的 2 倍绘制，应在阅读绘制坐标上统一再乘 2。字号、边距、行距与命中区域使用同一变换，只做一次。不要同时把 Paint 字号乘 2 又额外重复缩放文字。

反向映射阅读坐标、段落高亮与命中区域时也使用同一变换。工具栏和焦点框作为普通 View 保留原 dp/sp。这里的 @4 是目标画布换算；不能覆盖 `Resources`、强改系统 density，或把普通 View 全部放大成“原生 4K UI”。

| 区域 | 960×540dp | 640×360dp |

| 标题与内容、内容与底栏间距 | 16dp | 12dp |
| 中间滚动区域 | `minmax(0,1fr)`，按剩余高度分配 | 同左，首屏保留主状态 |
| 主标题 | 26sp，1.3 行高 | 23sp，1.3 行高 |
| 当前效果标题 | 22sp，1.4 行高 | 22sp，1.4 行高 |
| 正文 | 22sp，1.8 行高 | 同左，不缩小 |
| 模式主标签 | 16sp | 16sp |
| 常规操作、说明、设备数值 | 14sp | 14sp |
| 辅助标签 | 12–13sp | 12–13sp |
| 模式行 | 最小高 72dp，内边距 12×16dp，间隔 12dp | 同左，超出可滚动 |
| 一般按钮 | 最小高 / 宽 44dp；内边距 8×16dp | 同左 |
| 底部操作区域 | 内容自适应，顶部留 12dp，按钮间隔 12dp | 同左 |

标题、说明、帮助均采用自然行高。不给两行说明指定单行固定高度；字体放大时由中间内容滚动承担增加的高度。按钮标签保持单行，多个按钮可换行排列，底栏随内容增高。

本次沿用既有侧栏与内容边距。720p 进入显示面板时焦点在底部主动作，避免把模式行强制滚入后挤走首屏主状态；上下键可访问整个滚动区。底栏与头部参与正常网格布局，不用覆盖正文的固定定位或负边距拼接。

## 状态与事件约定

状态数据至少分为：用户偏好、设备能力、当前阅读会话、请求代次、请求目标、实际画布与路径、首帧完成、阅读位置。UI 文案从实际字段派生；请求目标不进入“实际阅读画布”。

| 阶段 | 面板文案 | 实际阅读画布 | 可用动作 |
| --- | --- | --- | --- |
| 未打开书籍 | 进入书籍后确认 | 未进入阅读 | 选择模式、设备详情、打开阅读 |
| 自动请求 / 兼容确认 | 正在确认阅读清晰度 / 正在确认兼容阅读 | 正在确认 | 返回、改用兼容、继续等待 |
| 独立画布确认成功 | 高清阅读 4K | 3840×2160 | 返回阅读、切换模式 |
| 兼容确认成功 | 系统清晰度 | 系统实际尺寸 | 返回阅读、选择自动 |
| 高清请求失败，正在恢复 | 正在恢复原有阅读 | 正在确认 | 返回、等待系统阅读恢复 |
| 原有阅读恢复完成 | 已回退到系统清晰度 | 系统实际尺寸 | 继续阅读、菜单内再次尝试、改兼容 |
| 原有阅读也未恢复 | 阅读显示暂不可用 | 尚未完成确认 | 重试兼容阅读、返回设置 |
| 原生 4K 系统 | 系统清晰度；说明系统与阅读均为 4K | 3840×2160 | 沿用系统阅读，兼容选项仍有效 |
| 面板不是 4K / 未知 | 系统清晰度 | 系统实际尺寸 | 沿用系统阅读，不声称高清能力 |

### 请求与确认

1. 打开书籍时保存当前位置并启动本次确认。普通 UI 的测量与阅读画布的测量分别记录。
2. 自动模式仅在确认存在 4K 能力且系统 UI 低于 4K 时尝试独立高清路径。原生 4K 系统沿用系统路径；未知能力不猜测 4K。
3. 发出请求只进入确认中；不会凭请求参数、面板尺寸、机型名称或成功创建 Surface 对象显示 4K。
4. 当前请求代次一致、实际尺寸匹配、路径匹配、首帧完成后，才提交结果。若回调尺寸低于请求，按未能启用处理。
5. 高清路径失败或超时，恢复原有阅读。只有系统画布恢复并绘制完成后，才显示“已回退”。保留自动偏好，不反复自动重试，不改变语音引擎。
6. 设备变化、退出阅读、Surface 销毁或后台恢复重建时立即使旧确认失效。异步回调需要带会话 / 请求代次，旧请求不能覆盖新选择。

原型的成功模拟等待约 1.8 秒；回退恢复约 0.7 秒；超时样例约 4.8 秒。它们用于展示状态，不是设备性能承诺。原生可先采用 3–5 秒有界确认超时，再通过实际设备观察调整；超时后不得循环黑屏等待。

`SurfaceHolder.setFixedSize()` 是尺寸请求方法，需在 SurfaceView 所属窗口线程调用；应结合生命周期与实际回调尺寸处理，不能把调用返回当成显示成功。[SurfaceHolder](https://developer.android.com/reference/android/view/SurfaceHolder)

`surfaceChanged()` 提供新宽高；Surface 只在创建与销毁回调之间有效。尺寸回调后仍需完成当前代次的实际绘制，再更新成功状态；本规格的首帧门槛是保守的产品判定规则。[SurfaceHolder.Callback](https://developer.android.com/reference/android/view/SurfaceHolder.Callback)

显示模式的 physical width/height 描述特定输出模式的像素尺寸，不等于读取到了真实面板铭牌尺寸。面板能力、当前输出与应用 UI bounds 要分别取证；不能把支持模式中最大的尺寸当作当前实际阅读画布。[Display.Mode](https://developer.android.com/reference/android/view/Display.Mode)

## 遥控器、滚动与位置

| 场景 | 操作 |
| --- | --- |
| 设置与显示面板 | 上下依顺序移动并滚入目标；左回侧栏，右回主区原焦点；同排底部按钮用左右选择 |
| 模式行 | 上下选择目标行，确定切换；已选与焦点独立 |
| 设备详情 | 确定展开 / 收起；设备数值区可聚焦，长内容可滚动查看 |
| TXT 正文 | 左右翻页，上下滚动，确定打开菜单 |
| PDF 100% | 上下滚动；示例中左右换页，也可通过页码跳转选择 |
| PDF 放大 | 上下滚动，左右平移，确定打开菜单 |
| 阅读菜单与跳转层 | 焦点限制在当前层；返回先关跳转，再关菜单，再离开阅读 |
| 显示面板返回阅读菜单 | 恢复“显示与清晰度”的焦点与正文位置，不自动跳页 |

原生切换画布前记录文本章节与内容锚点，而非只记像素滚动距离；PDF 保存页码、缩放值与页面坐标锚点。切换渲染后从这些锚点恢复，不能因像素密度翻倍把滚动位置翻成其他内容。浏览器示例保留合成页码、缩放与各页滚动位置，用于交互说明，不替代原生分页算法。

阅读菜单打开时背景不可操作；Tab 也限制在当前菜单或跳转层。关闭后按稳定标识恢复焦点，不复用已经移除的 DOM / View。焦点滚动留出 6–8dp 轮廓余量。首屏主状态与主动作占独立区域，帮助和详情即使很长也不裁字。

## PDF 渲染落地

- 100% = 适合可用阅读区域宽度，不是物理纸张尺寸，不是 bitmap 的像素对像素倍率。
- 正文层横向撑满阅读区域；文档内部留白属于 PDF 本身。工具面板覆盖时不重算 PDF 的适合宽度，关闭工具不跳动。
- 长页上下滚动；放大后允许横向平移。100%、150%、200% 是本交互稿的演示档位；适合屏宽回到 100%。
- 以当前缩放与实际阅读画布计算 PDF 到目标像素的变换，渲染可见块和少量邻近块，禁止先生成放大后的整页巨型 bitmap。
- 建议从 512×512px 块起步，ARGB_8888 单块约 1MiB，缓存以字节预算管理；实际块尺寸和预算应根据电视内存与滚动表现调整，不按 4K 页面的完整高度一次分配。
- 缩放、换页、切清晰度使不匹配代次的分块结果失效；旧块不能覆盖新位置。旧画面可暂留作过渡，但不把放大的旧低清块称作高清渲染完成。
- PDF 与纯图片沿用原有阅读边界，不增加 OCR、正文搜索或文字朗读。

Android API 21 的 `PdfRenderer.Page.render(Bitmap, Rect, Matrix, int)` 支持目标裁剪与仿射变换，官方明确将其用于分块或条带渲染。实际实现需根据页面坐标和块原点设置变换；本网页仅用 HTML 合成页面演示动作，不执行 PDF 分块。[PdfRenderer.Page](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer.Page)
