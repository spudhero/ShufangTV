# 书房 TV · 网盘来源界面规格

本轮交付独立的 `cloud-library.html`，样式为 `css/cloud-library.css`，交互为 `js/cloud-library.js`。沿用既有暗色书房，不修改 `index.html`、既有阅读页及其样式、脚本。原生 ShufangTV 仓库只读；没有执行 Git、修改 APK 或访问真实网盘、账号。

## 预览与范围

- 在本项目目录执行 `python3 -m http.server 4177 --bind 127.0.0.1`，打开 `http://127.0.0.1:4177/cloud-library.html`。当前会话已启动该服务；若端口仍在使用，无须重复启动。
- 主稿也能直接双击打开。在线阅读、本地/USB、SMB、WebDAV 通过同目录 `index.html` 复用既有流程；部分浏览器限制 `file:` 页面间访问，此时使用上述 HTTP 方式。
- 画面上方是独立的设计预览工具，不属于 Android TV 产品。四个页签直接切换来源、扫码、文件夹、浏览；下方选择器控制未连接、无来源、加载、空目录、分页和错误等状态。
- 方向键移动焦点，Enter 确定，Escape/Backspace 返回；F6 在电视界面和预览工具间切换。鼠标与键盘使用同一组控件。
- 扫码流程依次点击外部工具的“模拟扫码 → 模拟确认授权 → 模拟授权完成”。也可以单独停留在等待、已扫码、授权中或过期状态。
- 所有账号、目录和文件是内存中的预览数据；刷新或“重置示例”回到初始状态。新网盘流程不持久化身份信息、票据或密码，没有外部字体、CDN、网络请求或大型运行依赖。

## 审计结论

依据本轮提供的 `sources.png`、`cloud-login.png`、`cloud-folder.png`，以及既有 `index.html` 和设计 tokens：

| 原生截图中的问题 | 本稿采用的调整 |
| --- | --- |
| 四个网盘以近似文字按钮呈现，本地大卡片反而占据主要空间 | 网盘变成一排全卡可聚焦入口；常用来源处于中部；本地、USB、SMB、WebDAV 收到下方紧凑区域 |
| 尚未明确表达账号与来源的关系 | 上层“网盘账号”表达连接状态，下层“书籍文件夹”表达阅读入口；一个阿里账号对应文学、技术两个来源 |
| 灰色扫码对话框与暗色应用割裂，刷新和取消相距过远 | 自定义深色弹窗，左侧白底二维码、右侧步骤与状态；底部集中放刷新和取消 |
| 文件夹确认按钮出现在目录上下文之前，缺少存储位置与步骤线索 | 全屏第二步：先选资源库或备份盘，再浏览路径；底部将当前目录与确认动作绑定 |
| 初版大面积留空、操作权重接近，遥控焦点不够突出 | 固定内容层级、明确行高；焦点使用独立浅色轮廓，次要动作移入管理菜单 |

浏览来源页是本轮补齐的设计，不宣称第三张截图已包含该页面。图形标识采用阿、百度、Q、UC 的轻量文字构形，用于离线预览，不冒充官方商标资源。

## 四页结构

### 1. 书籍来源

侧栏宽 164dp，保留书房品牌、返回既有首页与当前来源栏目。主内容左内距 28dp、右内距 44dp，区块间距 16dp。

从上到下依次为页面标题、网盘账号、书籍文件夹、本地与家庭存储、遥控按键提示。四张网盘卡片等宽、间距 12dp；卡片整体是一个焦点，不把图形和名称拆成多个停靠点。

初始状态只有一个已连接的阿里账号，其资源库下已有 `我的书籍/文学` 与 `我的书籍/技术`。来源行主区域打开书籍，行末 44dp 操作区管理来源。路径过长省略，管理中的“查看完整位置”可展示全部文字。

已连接网盘卡片显示“已连接 · 管理”，按确定进入添加文件夹、重新登录、退出账号菜单。退出需要确认，并保留来源位置；来源行改为“需登录”，打开时进入扫码，完成后返回目标来源。移除来源也要确认，只移除入口，不删除云端文件。

空状态分别表达“尚未连接账号”和“账号已连接、尚未选择文件夹”。不展示未知书籍数量、速度或剩余容量。

### 2. 扫码登录

弹窗宽 744dp，内边距 24dp、圆角 10dp，使用内容表面色；遮罩为 `#0b0e0c`、约 73% 不透明度，无模糊。上方为网盘名称与 `1 / 3 · 扫码连接账号`。

左侧二维码纸面 **232 × 232dp**，右侧与其间隔 32dp，说明为三步：打开对应应用、扫码、确认授权。UC 必须写“使用 UC 浏览器扫码”。右侧状态区展示等待扫码、已扫码、授权中、已过期，并提供一行具体提示。

初始焦点放在“刷新二维码”。刷新与取消集中放在底部；过期时二维码覆盖过期说明，刷新成为琥珀主动作。右上关闭和返回键均可退出，并恢复到原网盘卡片。

本稿二维码是**不可解码、不可登录的合成矩阵**，使用本地 SVG 绘制，29 模块内容区外保留四模块白色安静区。没有复制或解码参考截图中的票据。原生接入真实票据时，应按真实 QR 编码库输出保留至少四模块安静区，不叠加文字或标识；二维码刷新、授权、取消及生命周期终止均须取消旧请求，防止过期回调跳转。

### 3. 选择书籍文件夹

全屏布局保留顶部返回、标题、账号与 `2 / 3`。纵向分配为：52dp 页头、44dp 位置栏、弹性目录区、64dp 底部确认区，间隔 12dp，整体留在 540dp 内。

阿里先显示“资源库”和“备份盘”两个可聚焦位置，选择前不能保存。其他网盘直接进入根目录；原生位置标识应使用实际服务返回的稳定 ID，不能仅凭显示名称推导。

位置栏含“上一级”、面包屑和完整路径按钮。列表行 48dp、间隔 4dp；名称单行省略，进入后可通过完整路径查看全部名称。分页示例一页四行，不显示未知总数。进入子目录再返回时恢复页、滚动位置与触发目录焦点。

底部左边展示当前文件夹，右边固定“将此文件夹设为书籍来源”。说明保持“只保存位置，不下载整个文件夹”。空目录也能成为来源；读取中/读取失败时保存按钮明确不可用，错误提供重试，返回始终可用。重复位置展示“已经添加”，提供打开已有来源的动作。

#### alpha.4 原生交互修订

保留上述 OpenDesign Cloud / Local Codex 原稿作为设计来源；本轮沿用暗色书房、固定底部操作和遥控焦点规则修订原生流程。选择页请求完整条目，先显示子文件夹，再显示支持的书籍及格式 / 大小，避免含书籍的目录看起来为空；MP3 等非书籍不进入阅读列表。分页改称“下一页内容”，空状态仅描述当前页。

底部动作改为“使用并浏览书籍”，保存后直接进入来源目录。选择书籍时添加或复用当前来源，重新核对实际文件列表后显示在线 / 离线操作面板；停在列表或面板不读取正文。重复选用已有文件夹直接浏览，不再回到来源列表。新增仅含书籍的目录、重复来源、无隐式下载和 720p 固定操作回归。本段是原生修订记录，不声称原浏览器稿已经重新生成。

### 4. 浏览来源

顶部显示来源名、所属网盘与存储位置、在线状态；新建来源后短链路显示 `3 / 3`。面包屑和父目录导航沿用文件夹页，避免焦点规则变化。

每行 48dp。文件夹使用线性文件夹图形；书籍使用 EPUB、TXT、PDF 文字类型标识。只展示本地示例已知的名称与类型，缺失大小、页数或修改时间时直接省略。

选书后打开 584dp 宽动作面板，名称完整换行。两项动作各至少 80dp 高：

- **在线阅读**：说明“按需读取”，唯一琥珀主动作、默认焦点。
- **保存离线**：说明“占用本地空间”，独立的次级动作。

本稿在线动作将对应的示例古籍交给既有阅读界面，不更改其设计；PDF/TXT/EPUB 标签是类型呈现示例，不意味着这里实现了解析器或真实云端传输。保存离线只发出 `cloud-preview:mode-selected` 选择事件，并在产品画面外记录交接结果；不创建文件、不显示虚假的下载进度或保存成功。

## 遥控焦点与返回

- 焦点：`#f8e2b6`、2dp 实线、外偏移 3dp、缩放 1.018。容器为焦点轮廓预留至少 6dp，不裁切子控件。当前栏目则用背景、琥珀文字和竖标记表达，未聚焦时仍可辨认。
- 进入/移动 180ms ease-out；按下缩放 0.99。启用减少动态效果时关闭过渡和焦点缩放，保留轮廓。
- 方向键优先找同一行/列最近控件，不在边界自动循环。Tab 在电视当前作用域内循环；F6 是设计预览快捷键，原生不需要。
- 弹窗打开时背景不可交互，方向键、Tab 只在该弹窗内移动；嵌套确认关闭后先恢复上一级菜单。所有动作有可访问名称，禁用按钮用文字/状态说明原因，保留可辨认的焦点。
- 返回顺序：当前弹窗 → 当前子目录 → 阿里存储位置选择（如适用）→ 书籍来源 → 既有书房。阅读菜单和目录沿用原有返回行为，退出阅读恢复到浏览来源中的那本书。
- 原生恢复锚点使用账号 ID、存储位置 ID、目录/文件 ID 加分页游标，不使用可变的行号作为唯一身份。数据刷新、删除或登录失效导致原节点消失时，落到同区第一个有效动作。

## 原生落地边界

账号连接态、来源位置和书籍操作应分开保存。建议最小模型为 `Account(provider, accountId, authState)`、`Source(sourceId, accountId, driveId, folderId/path, displayName)`，以及一次性的在线/离线阅读意图。一个账号可以关联多个来源；移除来源不应等同于退出账号。

颜色、字号、间距、圆角、边线及文字标识均可用原生资源、View 和 Canvas 实现；不需要 CSS 渐变、模糊或大图。真正新增的账号/来源关系、全屏文件夹流程、焦点恢复、扫码状态取消和两个阅读模式，需要在原生界面及业务层落地，不能用颜色或字体资源补丁替代。

原生二维码、账号标识、目录分页、文件大小、在线读取、下载能力必须接真实接口。不要把本稿的示例数据、合成二维码、外部状态工具、iframe 联动或 DOM 焦点算法搬进 APK。原生需连接已有文件浏览与阅读入口；下载应先检查本地空间并使用真实任务进度。本稿未修改、编译或验证 Android APK。

## 1080p 与 720p

| 输出场景 | 960×540 设计坐标映射 | 关键尺寸示例 |
| --- | --- | --- |
| 1920×1080 | 2× | 48dp 行高对应 96px；12sp 说明在默认字体比例下约 24px；二维码 464px |
| 1280×720 | 4/3× | 48dp 行高对应 64px；12sp 说明约 16px；二维码约 309px |

上述是输出映射示意。Android 实际密度由系统配置决定，应使用 dp/sp 和运行时可用尺寸，不根据面板分辨率硬编码 density。两种输出维持相同信息架构、四网盘横排和焦点顺序，不切换为手机布局。

遇到系统字体放大，优先让说明折行、目录区内部滚动，并保证底部确认区可见，不缩小文字抵消字体偏好。实际 QR 按整模块像素绘制并保持安静区。1080p/720p 均需在 2–3 米观看距离检查中文细笔画、焦点边界、过扫描裁切和快速连续方向键。
